APEX GP / rCTF — ONE RACE PER INSTANCE

This is the competition deployment. The Render Static Site remains a separate
browser-local preview and does not supply the shared event or instance lifecycle.

RULES
  Each created Kubernetes instance registers its team at infinite best time
  (shown as infinity; JSON null) and zero points.
  One instance grants one race: an out-lap plus one flying lap, maximum 10 min.
  A crash immediately invalidates and ends the race, even on the out-lap.
  Practice is hidden in competition instances.
  A faster valid time replaces the team's personal best across instances.
  A slower/invalid attempt never erases a previous best.
  Finished/invalid/abandoned instances are stopped automatically via rCTF.
  A fresh instance grants a fresh race; there is no three-attempt event limit.
  Valid finishers score dynamically from 1000 down to 200; ties share points.
  Unclassified teams remain on the central leaderboard at infinity / zero.

1. PUBLISH THE NEW IMAGE ON GITHUB
  Push the complete source, then run the manual GitHub Actions workflow:

    gh workflow run publish-image.yml --ref main -f tag=ctf-v2

  Wait for success. The image reference is then:

    ghcr.io/ashraful-notfound/apex-gp:ctf-v2

  The tag is only a deployment target until the workflow succeeds. Use the same
  image/digest for coordinator and gateways. Private GHCR images need registry
  credentials on the remote host and in instancer-created namespaces. Keep the
  source repository private if desired. No local application hosting is needed.

2. DEPLOY THE PERMANENT COORDINATOR ON A REMOTE SERVER
  Copy deploy/rctf/.env.example to .env and fill every placeholder.
  Choose one public HTTPS coordinator hostname, for example timing.aanafim.xyz.
  That example needs actual DNS and reverse-proxy configuration.

  Set:
    RCTF_URL=https://mock.ductf.com
    RCTF_CHALLENGE_ID=<actual rCTF challenge ID>
    COORDINATOR_PUBLIC_URL=https://<coordinator hostname>
    COORDINATOR_HOST=<coordinator hostname>
    INSTANCE_DOMAIN=<existing rCTF instancer domain suffix>
    INSTANCE_PREFIX=apex-gp-
    APEX_IMAGE=ghcr.io/ashraful-notfound/apex-gp:ctf-v2
    EVENT_ID=<fresh stable event ID>
    EVENT_START=<actual ISO start with timezone>
    EVENT_END=<actual ISO end with timezone>

  Generate separate secrets using openssl rand -hex 32 for:
    RCTF_SCORING_SECRET (also entered in rCTF scoring settings)
    APEX_COOKIE_SECRET (stays on the coordinator)
    APEX_GATEWAY_KEY (also entered in the team gateway YAML)

  Start on the remote server:
    docker compose --env-file .env -f deploy/rctf/compose.yaml pull coordinator
    docker compose --env-file .env -f deploy/rctf/compose.yaml up -d --no-build coordinator

  Route HTTPS to loopback port 8081 through the existing reverse proxy. The
  optional --profile https starts Caddy if public ports 80/443 are free.
  Verify https://<coordinator hostname>/healthz.
  Retain the coordinator's data volume and .env across restarts; run one process.

3. REGISTER rCTF SIGN-IN
  rCTF /admin/settings -> External apps:
    Name: APEX GP
    Redirect URI: https://<coordinator hostname>/auth/rctf/callback

  Put the generated client UUID/secret into RCTF_CLIENT_ID/RCTF_CLIENT_SECRET
  in the coordinator .env. Restart the coordinator after configuration changes.
  The callback must match exactly.

  The coordinator temporarily retains the team credential encrypted on its
  private volume so that it can stop that team's instance. Credentials are
  removed after shutdown/expiry/supersession. They never enter the gateway,
  browser storage or plain-text logs. Keep APEX_COOKIE_SECRET stable.

4. SET THE rCTF CHALLENGE
  Name: APEX GP — Race the Clock
  Category: misc
  Scoring kind: Dynamic
  Source transport: Webhook
  Source secret: same RCTF_SCORING_SECRET
  Minimum/maximum: 200 / 1000 (the coordinator calculates actual team scores)
  Flags: empty
  Tiebreak eligible: false
  Instancer: existing Kubernetes provider
  Integration ID: apex-gp
  Lifetime: 3600000 milliseconds (3600 seconds)
  Extendable: true

  Exposed endpoint:
    Protocol: https
    Prefix: apex-gp
    Container/pod name: game
    Container port: 8080

  Paste deploy/rctf/instance-kubernetes.yaml.example into Instancer config.
  Replace the image, both coordinator URLs and the gateway key.
  Preserve RCTF_EXPOSED_HOSTNAMES and RCTF_INSTANCE_NAMESPACE downward-API
  environment settings. The namespace supplies the owning team UUID so a
  scoreboard entry can be created at startup, before sign-in. Keep egress true.

5. OPEN THE CENTRAL LEADERBOARD
    https://<coordinator hostname>/leaderboard

  This remains available after an individual gateway is deleted. Both the page
  and in-game Timing update from the same authoritative classification.

6. TEST DURING AN OPEN STAGING CTF WINDOW
  rCTF public team profiles are unavailable before its start gate.
  Test instance startup registration, sign-in, a crash on both lap phases,
  completion, slower/faster replacement times, concurrent starts, reloads,
  coordinator restarts, disconnected browsers and retry after a platform outage.
  A used instance must never grant a second race. A fresh instance must.
  Verify Dynamic scores in rCTF and the end-of-event classification freeze.

  Version v4 changes competition rules. Use a fresh event/challenge, or have an
  organizer clear old staging scores before release. Never delete a real event's
  records or volume to reset an individual attempt.
